-------------------------------------------------------- SIDE EFFECTS ---------------------------------------
a side effect is any action a function takes that affects something outside of its own local scope.

In React, think of your component's main job as calculating the UI based on props and state. Anything that happens outside of that calculation—like fetching data, manually changing the DOM, or setting up a subscription—is a "side effect."


IMPURE FUNCTION - 
let total = 0;

function addAndLog(a, b) {
  const result = a + b;
  console.log(result); // SIDE EFFECT: Talking to the browser console
  total = result;      // SIDE EFFECT: Changing a variable outside the function
  return result;
}

PURE FUNCTION - 
// No side effects. Just math.
function add(a, b) {
  return a + b;
}

-------------------------------------------------------- useEffect ---------------------------------------

useEffect is a Hook that allows you to perform side effects in functional components.

The useEffect Hook tells React that your component needs to do something after the render. It takes two arguments:
1. A function: The code you want to run.
2. A dependency array (optional): A list of variables that determine when the effect should re-run.

Dependency Array 
No array - Run After every render - usage: Rarely used (can cause performance issues).
Empty array [] - Run Only once , after the initial mount - usage: API calls, starting a timer.
With variables [prop, state] - Run On mount and whenever those variables change -  usage: Updating UI based on a specific ID change.

## EXAMPLE - 
useEffect(() => {
    fetch(`http://www.omdbapi.com/?i=tt3896198&apikey=${KEY}&s=interstellar`)
      .then((res) => res.json())
      .then((res) => setMovies(res.Search));
  }, []);


# Cleanup - 
Sometimes, an effect needs to "clean up" after itself to prevent memory leaks (like stopping a timer or unsubscribing from a service). You do this by returning a function from inside useEffect.
useEffect(() => {
  const timer = setInterval(() => {
    console.log('Tick');
  }, 1000);

  // Cleanup function: runs before the component unmounts
  return () => clearInterval(timer);
}, []);

🙋‍♀️ Why "Side Effects" Need Their Own Hook
React renders components frequently. If you put a side effect (like a network request) directly in the body of your function, it would run every time the component renders. This leads to:
 - Performance issues: Re-fetching data unnecessarily.
 - Bugs: Creating 100 timers instead of one.
 - Infinite loops: If the side effect updates state, which triggers a render, which runs the side effect again...

The useEffect hook acts as a "safe zone" for these actions, ensuring they only run at specific times (like when the component first appears).
