An entity represents a table in the relational database. An instance of an entity corresponds to a single row within that particular table.

For creating an entity, you have to use @Entity annotation 

By default, the name of the table will be same as that of the class. If you want to change the name of the table,
you can specify it like - 

import jakarta.persistence.Entity;
import jakarta.persistence.Id;
import lombok.Data;
import lombok.NoArgsConstructor;

@Data
@NoArgsConstructor
@Entity(name = "categories") // name parameter defines the name of the table
public class Category {
    @Id
    private Long categoryId;

    private String categoryName;
}

In application.properties file, if you write (usually use while development) - 
1. spring.jpa.show-sql=true
 - Prints raw SQL statements to the console
 - Helpful for debugging and understanding what queries are being run


2. spring.jpa.properties.hibernate.format_sql=true
 - Pretty-prints SQL with line breaks and indentation
 - Makes complex queries easier to understand


 3. spring.jpa.hibernate.ddl-auto=
 Defines what Hibernate should do with database tables when the application starts.

Values:
none – No action on database schema (default)
validate – Checks schema matches entities (no changes)
update – Updates schema automatically
create – Drops and recreates tables
create-drop – Creates tables at startup and drops on shutdown

## Difference btw create & create-drop?
create → Tables are recreated once when the app starts. (Drops existing tables (if they exist) -> Creates new tables)
create-drop → Tables are recreated at start and deleted again when the app stops.


------------------------------------ @Id & @GeneratedValue ----------------------------------------------------

@Id - is used to mark a field as the Primary Key of an entity.

@GeneratedValue(strategy = <<GENERATION_TYPE>>) - how primary key values are generated.

🔹 GenerationType Values
1️. AUTO
 - JPA chooses the strategy automatically
 - Depends on database & provider (Hibernate)
 - Default strategy
 
##EXAMPLE - 
@Id
@GeneratedValue(strategy = GenerationType.AUTO)
private Long id;

Supported Databases:
MySQL
PostgreSQL
Oracle
SQL Server
H2
🚀 Works with all databases

2. IDENTITY
 - Database generates ID using auto-increment
 - ID created during insert

 ## EXAMPLE - 
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;

Supported Databases:
MySQL (AUTO_INCREMENT)
SQL Server (IDENTITY)
PostgreSQL (SERIAL)
H2

❌ Not Supported
Oracle (no auto-increment)

🚀 Cannot batch inserts efficiently

3.SEQUENCE
 - Uses a database sequence

## EXAMPLE - 
@Id
@GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "user_seq")
@SequenceGenerator(
    name = "user_seq",
    sequenceName = "user_sequence",
    allocationSize = 1 // this means, every time you save a new record, the application has to ask the database: "What is the next ID?
)
private Long id;


IF AllocationSize = 50,  The app fetches 50 IDs at once and stores them in memory. This reduces database round-trips; faster bulk inserts.

Supported Databases:
Oracle
PostgreSQL
DB2
H2

❌ Not Supported
MySQL (no sequence support)

🚀 Most efficient strategy. Hence, Preferred for enterprise apps

4. TABLE
 - Uses a separate table to generate IDs
 - Database-independent

##EXAMPLE - 
@Entity
public class Order {
    @Id
    @GeneratedValue(strategy = GenerationType.TABLE, generator = "order_gen")
    @TableGenerator(
        name = "order_gen",
        table = "id_generator",
        pkColumnName = "gen_name",
        valueColumnName = "gen_value",
        pkColumnValue = "order_id",
        allocationSize = 1
    )
    private Long id;
    
    private String orderName;
}
Supported Databases: 
All databases (MySQL, Oracle, PostgreSQL, etc.)

❌ Slowest, rarely used


### WHAT WILL HAPPEN IF YOU DON'T USE GeneratedValue WITH ID ANNOTATION ?
If you use @Id without a @GeneratedValue annotation, you are telling the persistence provider (like Hibernate) that you will manually assign the ID yourself.

❌ If you forget to set it → will throw org.hibernate.id.IdentifierGenerationException.
Drawback - You must ensure uniqueness yourself. Otherwise, DB will throw primary key violation. Also, Every insert requires you to generate/track IDs manually.
